## Why

Today the "Maps…" button in the workspace sidebar (`src/components/Sidebar.svelte:192`) calls `goto(resolve("/"))`, which tears the user out of the workspace entirely: the map disappears, the panels disappear, and the bundle loader replaces the whole window until a map is opened again. The user's words on the UX review were direct — "мне не нравится что maps закрывает все окно. Надо либо красивее это делать (с превью карты может или еще как-то), либо в отдельном плавающем окне". They explicitly rejected the modal and the native-window variants in favour of a slide-in panel because it lets the workspace map stay visible alongside the loader.

The current routing structure (one route per surface, no nesting) is what forces this UX into a binary all-or-nothing switch. Reworking the "Maps…" affordance to open a shadcn `Sheet` overlay on top of the existing workspace keeps the map mounted, keeps the sidebar context visible, and matches the user's mental model — "I want to swap the active map" is a small contextual action, not a navigation event.

The current routing requirement in `ui-shell` ("Top-level surfaces live at distinct routes `/` and `/project`") will need to evolve: the bundle loader is no longer purely route-based. It remains the route at `/` for cold-start (no active map yet), but on top of an active workspace it lives as a Sheet inside `/project` rather than as a separate route the user navigates to.

## What Changes

- The bundle-loader UI (project list, maps column, status region) SHALL be extracted from `src/routes/+page.svelte` into a reusable component `src/components/BundleLoader.svelte` that owns no routing concerns and can be rendered both inside a route and inside a Sheet.
- The workspace sidebar "Maps…" button SHALL open a shadcn `Sheet` (`side="right"`, width ~480px) overlaying the workspace, rather than navigating to `/`. The Sheet SHALL render `BundleLoader` as its body. The workspace map SHALL remain mounted and interactive while the Sheet is open.
- The Sheet SHALL be closable via the X affordance, the Esc key, and click-outside (default shadcn `Sheet` behavior).
- Sheet open/closed state SHALL be a UI-only writable store (`bundleLoaderOpen` already exists at `src/lib/stores.ts:134`), not a URL search parameter. Rationale in design.md.
- The `/` route SHALL be preserved as the cold-start entry point: when there is no active map in the store, the application SHALL still land on `/` with the bundle loader rendered as the full-window primary surface, just as today. The Sheet variant is the on-top-of-workspace experience, not a replacement for cold-start.
- Opening a map from the Sheet (in workspace context) SHALL close the Sheet and let the workspace re-render with the new active map; the user SHALL NOT be navigated to a different route in the process.
- The shadcn-svelte `sheet` primitive SHALL be added to `src/lib/components/ui/sheet/` via `npx shadcn-svelte@latest add sheet`. The primitive list in the `ui-shell` spec SHALL be updated to include it.

## Capabilities

### New Capabilities
- _none_

### Modified Capabilities
- `ui-shell`: the routing requirement is relaxed so that the bundle loader can also appear as a Sheet overlay inside the workspace. The "Maps…" button no longer navigates. The primitives list adds `sheet`.

## Impact

- **Frontend**: `src/routes/+page.svelte` becomes a thin wrapper around the new `BundleLoader` component; `src/components/BundleLoader.svelte` is created with the markup currently inline at `src/routes/+page.svelte:213-384`; `src/components/Sidebar.svelte:188-196` replaces the `goto(resolve("/"))` call with a `bundleLoaderOpen.set(true)` toggle and hosts the `Sheet` JSX; `src/lib/components/ui/sheet/` is generated by `shadcn-svelte add sheet`; `src/lib/stores.ts` already exposes `bundleLoaderOpen` so no new store is needed.
- **Backend**: no change. No new IPC commands, no new events. (A separate, optional follow-up change could add `get_map_preview` for thumbnails — see design.md.)
- **Spec evidence**: smoke that clicking "Maps…" in the workspace opens a right-side panel without unmounting the map; that opening a map from the panel closes the panel and updates the active map in the workspace; that cold-start without an active map still lands on `/` with the loader full-width.
- **Risk**: low. The bundle-loader code being moved is self-contained, all backend interactions go through `src/lib/api.ts`, and the Sheet primitive is a standard shadcn-svelte component with established `bits-ui` semantics. The chief risk is regressing the "MapView is mounted once" requirement; the Sheet renders into the same DOM tree without replacing the workspace, so MapView's mount lifecycle is unaffected.

## Out of scope

- **Catalog persistence / cache** (a separate proposed change): the Sheet shows whatever the bundle loader shows today; speeding up the catalog fetch is orthogonal.
- **Per-map streaming availability** (a separate proposed change): the Sheet is a host for the bundle loader; per-map cached/streamable detection logic is unchanged here.
- **Listener consolidation** (the proposed `consolidate-state-event-flow` change): touching the event subscriptions belongs there, not here. This change MUST NOT introduce new `listen()` registrations or relocate existing ones.
- **Map preview thumbnails next to each map row**: explicitly out of scope. The user's "с превью карты может" suggestion is acknowledged but deferred — implementing it requires a new backend IPC (`get_map_preview(map_path) -> png_bytes`), a thumbnail cache, and asynchronous loading semantics, all of which are large enough to warrant their own proposal. Decision and rationale in design.md.
