# Лесной поиск в OziExplorer — вторая и третья запись

Выжимка из двух аудиозаписей владельца от 08.10.2026. Первая — лесной поиск,
второй день: треки и точки с навигаторов и телефонов, комплекта карт нет
(его не заказывали). Вторая, короткая — городской поиск, один трек, и
загрузка результата. Продолжение `2026-10-06-track-processing-in-ozi.md`;
повторы убраны, позывные и места не переносятся.

## Что пришло

- На одну группу — по несколько файлов: трек с навигатора, трек с телефона,
  отдельные GPX с точками за разные дни (после смены даты навигатор начал
  новый файл). Имена файлов — как попало: дата-время, позывной, «File».
- Один GPX бывает и треком, и точками сразу (телефон); в Ozi при загрузке
  они расходятся, и это правильно.
- Треки с телефона большие: 18 000 точек, «долго открывается»; после
  фильтра 4 всё равно около 1000.
- Описания точек с телефона — адрес, автоматически («бестолково
  абсолютно»); в одном треке описание в поехавшей кодировке.

## Цикл на трек (что делал руками)

1. **Хвост с прошлого поиска.** Навигатор приехал с другого поиска: в начале
   трека точки за 26 сентября, 2 октября. Без карты поиска обрезает по дате
   — «было очевидно, где начинался новый поиск». Выделял точки в списке и
   удалял; «можно было бы как-то удобнее».
2. **Выбросы** — удалял по точке; несколько подряд — **выделением на карте**:
   панель Selection Control в Ozi, «нарисовать бокс, чтобы выбрать точки на
   активном треке», потом «удалить выбранные». Пользовался ею постоянно;
   выбирать в списке с 572-й по 586-ю — «уже неудобно».
3. **Выброс или нет — по скорости:** «24 км/ч — не пешая скорость, как
   будто их выкинуло из штаба». Иногда не уверен: большие расстояния, «может,
   поехали на машине». Сомнение решает время между точками.
4. **Начало и конец у штаба** — первые и последние точки в застройке
   срезает («возврат до штаба»).
5. **Имя.** Дата — по выходу группы: вышли до смены даты — 7-е, после —
   8-е, даже если файл прислали 8-го. Стандарт (п. 16) мягче: дата
   «примерно по дате начала или окончания задачи, переход через полночь не
   принципиален», возможна привязка к сменам координатора. Позывной — из имени файла, если похоже
   на позывной; два трека одной группы — `Lisa19_1`, `Lisa19_2`, без личного
   позывного, если не ясно, чей.
6. **Цвет по поисковому дню** (схема из п. 21 стандарта). Поисковый день —
   не календарная дата, а ночь работы: первый день — с 6-го на 7-е, его
   треки предыдущий ОК покрасил красным; второй — с 7-го на 8-е, его треки
   владелец красит синим все, хотя одни начались 7-го, другие 8-го. То есть
   цвет и дата в имени трека считаются по-разному: дата — по выходу группы,
   цвет — по поисковому дню. Два трека одной группы — сначала разные
   оттенки синего, потом «пускай будет одинаково». (Уточнено владельцем
   08.10.2026.)
7. **Фильтр 4** — после обрезки; в Ozi создаёт новый трек, старый удалить.
8. **Сохранить PLT, переименовать исходный GPX** так же: «очень не хватает —
   в одном интерфейсе переименовывать и GPX, и сохранять PLT, чтобы
   одинаково назывались».
9. Поднять трек выше в списке треков.

## Точки (waypoints)

- Точки приходят файлами за число, и в одном файле — точки разных лис
  (как и требует стандарт: п. 29 — файл `Waypoints_ГГГГММДД`, п. 31 — в
  идеале один файл на поиск). В Ozi открытие второго GPX **затирает** точки
  первого; чтобы видеть все сразу, сохранял их в `.wpt` и подгружал.
- Отбор **по смыслу** (п. 30 — удалять точки без семантики): точка с одними
  цифрами, фото без смысла. Точки за 7-е отпали целиком, потому что по
  смыслу оказались не нужны, а не из-за даты. (Уточнено владельцем
  08.10.2026.)
- Описание с телефона — стереть у всех.
- По ответу координатора (форум): выгружаются только **точки заброса**,
  область «не заливаем».
- Оформление: заброс — передний цвет чёрный, задний — лаймовый, номер в
  описании; камера — с азимутом (хотел «ровно на восток, 90°»), как это
  записать — «вообще не очевидно». Залил на пробу — на сайте всё равно
  синие флажки; цвет одной камеры забыл поменять. Ни заброса, ни камеры, ни
  азимута в стандарте нет — это из лекции ОК+, её текста у нас нет.
- Хотел бы: навести на точку на карте и увидеть, что это за точка, найти её
  в списке.

## Что стандарт говорит о точках (п. 26–32, 35–36)

Сверено с текстом стандарта ред. 06.03.2025 (прочитан 06.10.2026; 08.10
Yonote отвечал 503).

- **Имя точки:** русские и латинские буквы, цифры, пробел, `_`, `-`;
  заглавная русская «С» заменяется латинской «C»; предпочтительно по-русски,
  коротко, не капсом; подробности — в примечании. Проблемы с русским или
  заливка в навигатор — транслит (п. 27).
- **Цвет (п. 28, рекомендация):** важные для поиска, подтверждённые
  артефакты — красные; неподтверждённые артефакты — цвет морской волны;
  положения групп, особенности местности — зелёные.
- **Файл (п. 29):** только латиница, цифры, `_`, `-`; начинается с
  `Waypoints_`, дальше дата `ГГГГММДД`. Сохраняется прямо в `10-Tracks`
  (п. 25).
- **Отбор (п. 30):** удалять точки без важной семантики, например
  вспомогательные точки группы; в сомнении — спросить того, кто ставил.
- **Файлов — минимум (п. 31),** в идеале один.
- **Точка обнаружения — `BVP`** (`BVP1`, `BVP2` при нескольких пропавших,
  п. 32); файл с `BVP` выкладывается только с отдельной санкции
  координатора (п. 36); важные точки — после консультации с ним (п. 35).

## Область

Задача «всё в воде, где нет трека» — область с маргиналами: прямоугольник с
вырезом, особенность местности, зелёным. Это ОК+ («нам нужно будет уметь»);
по ответу координатора — не заливать.

## Папки и загрузка (вторая запись)

- Непонятно, к какому поиску относится присланный GPX: сначала найти, потом
  создать папку и перенести туда GPX. С PLT проблемы нет — Ozi сохраняет куда
  скажешь и умеет создать папку из диалога.
- Загрузка — отдельным FTP-клиентом; имя папки поиска копирует из Finder.
- Хотелось бы видеть список треков поиска на сайте (не только список
  поисков), и ошибки обработки — но они за логином.
