# Разбор треков в OziExplorer — как это делает оперативный картограф

Выжимка из аудиозаписи владельца от 06.10.2026: реальный поиск, обычный
OziExplorer, без комплекта карт (только OSM). Повторы убраны, порядок и
решения сохранены. Это источник для CJ-4 и CJ-6 (`docs/customer-journeys.md`).

## Исходное

- В поиске уже лежат треки от двух групп в PLT. Имя по стандарту:
  `ГГГГММДД_Группа_Позывной`, латиницей (`20261006_Veter1_Maura`).
- Новые треки приходят GPX-файлами — по одному на экипаж, имя файла как
  попало (`File.gpx`, `20261006-Veter1-Maura.gpx`).
- Группы: «Ветер N» — автомобильные экипажи, «Лиса N» — пешие.

## Цикл на один трек

1. Импорт одного GPX.
2. Найти трек: выделить, открыть список точек, кликнуть первую — карта
   переходит к ней; отдалить, чтобы увидеть трек целиком.
3. **Разрывы.** GPS не писал — участок без точек, а в треке он соединён
   прямой. Действие: «удалить точку и разделить трек» в этом месте. Владельца
   устроило бы и просто «разделить трек на сегменты в этой точке».
   Решение не механическое: если прямая правдоподобна (ехали прямо по
   дороге), разрыв оставляют.
4. **Выбросы.** Точки там, где люди не могли быть (через реку, в сторону и
   обратно, спуфинг GPS на мосту Александра Невского). Удаляются; если после
   этого получается скачок — тоже с разделением.
5. **Проверка правдоподобия по времени.** Смотрит время соседних точек
   (`3:14` → `4:49`) и расстояние между ними: «за это время такое расстояние
   пройти не могли» — значит выброс, а не путь.
6. **Переименование** по стандарту: дефисы → нижние подчёркивания, латиница;
   номер экипажа без лишнего (`Veter2_Granta` → `Veter2`).
7. **Цвет по группе.** «Ветер» — розовый; «Лиса» — синий или красный. Старые
   треки другого картографа раскрашены иначе — их перекрашивает.
8. **Фильтрация** (в Ozi: «фильтр трека», «индекс 4»). Сокращает точки.
   В Ozi создаёт **новый** трек: имя и цвет теряются, старый надо удалить,
   название скопировать, цвет выбрать заново — «это неудобно», повторяется на
   каждом треке.
9. Проверить, что время первой точки — правильная дата.
10. Сохранить в PLT в папку треков, имя файла = имя трека.

После всех треков — загрузка результата (позже — FTP, см. `ftp-accounts`).

## Что ещё делал по ходу

- Проверил, отфильтровал ли треки предыдущий картограф: сравнил число точек
  до и после фильтра (1097 точек — «не отфильтрован»).
- Трек на 20 000 точек в Ozi «грузится долго, работает медленно» — так быть
  не должно.
- «Было бы удобно, если бы можно было отменить» — в Ozi нет undo.

## Сверка с ozi-rs (на 06.10.2026, по коду)

| Шаг | В ozi-rs | Чего нет |
|---|---|---|
| Импорт нескольких GPX | есть: «Импорт…» с множественным выбором, импорт папки | — |
| Список точек → перейти на карте | есть: таблица точек инспектора, «Показать на карте» | — |
| Удалить точку | есть: контекстное меню точки на карте | — |
| Разделить в точке | есть: «Разрезать сегмент здесь» в таблице точек | **одного действия «удалить и разделить»** нет; оба шага — в разных местах |
| Найти разрывы и выбросы | только визуально; в проигрывателе — «тишина» > 5 мин | **подсветки/списка скачков** (расстояние, время, скорость между соседними точками) нет |
| Время и скорость между точками | время точки в таблице есть | **скорости/расстояния до соседней точки** нет |
| Переименование по стандарту | есть предупреждение о формате имени | **исправления в один клик** (дефисы → `_`, транслит) нет |
| Цвет по группе | палитра раздаёт разным экипажам разные цвета | **правила «группа → цвет»** (Ветер = розовый) нет |
| Фильтрация | «Упростить» (Douglas–Peucker, допуск в метрах) меняет трек **на месте** — имя и цвет сохраняются, есть undo | соответствие «индексу 4» Ozi неизвестно |
| Сохранить PLT в папку треков | есть: «Экспорт PLT» по одному треку, по умолчанию в `10-Tracks/` | **пакетной выгрузки «каждый трек — свой PLT»** нет |
| 20 000 точек | не проверялось на таком треке в интерфейсе | — |
| Отмена | есть: Cmd+Z / Cmd+Shift+Z | — |

## Что говорят стандарт и вики отряда (прочитано 06.10.2026)

Источники: [Картографический стандарт для ОК](https://lizaalert.yonote.ru/share/start/doc/kartograficheskij-standart-dlya-ok-xRqRCLS7Jw)
(ред. 06.03.2025) и статьи раздела «Работа с треками» вики
«Вики.Картография» (там же, `share/start`). Обязательные пункты стандарта
выделены в оригинале красным; здесь — то, что касается кода.

**Порядок обработки (п. 7–9):** обрезка по зоне поиска → ручная обработка
(хвосты, уже обработанные задачи, выбросы, разрывы) → фильтрация. Не наоборот:
статья «Обработка трека без подгруженной карты» показывает трек, который
деформировался, потому что часть в 90 км от зоны отфильтровали вместе с
нужной.

**Фильтрация (п. 10–13):** пешие и смешанные — «по индексу 4» всегда;
Ветра, Борты, БПЛА — «если ОК видит смысл», тоже индекс 4. БПЛА со сплошной
съёмкой: сначала перелёты и пропуски кадров (интервал между соседними точками
вдвое и больше обычного) — как разрывы, потом фильтр.

**Что такое «индекс 4» — не выяснено.** Справка OziExplorer
([Track Filter](https://www.oziexplorer4.com/eng/help/track_filter.html)):
«чем выше индекс, тем меньше точек; по умолчанию 5»; есть второй режим —
«число точек». Алгоритм не опубликован ни в справке, ни в истории версий, ни
в вики отряда («ВСЕГДА фильтруем через 4» — без объяснения). Выяснять
эмпирически: пары «исходный GPX → PLT после фильтра 4» из реального поиска,
проверка, какие точки выживают (подмножество ли это исходных, что
предсказывает их отбор — расстояние, угол, отклонение от хорды).

**Выбросы (статья «Удаление точек из трека…»):** в списке точек Ozi выброс
виден по столбцам Dist и KPH — к «вершине» 351 м на 62 км/ч, от неё 342 м на
246 км/ч. Удалять надо **только вершину**; удаление соседней точки выброс не
убирает и деформирует трек. Причины: плохой сигнал, спуфинг у режимных
объектов, фоновые ограничения телефона. «Ежи» — густые всплески точек.

**Имя трека (п. 14–19, 24):** только латиница, цифры, `_` и `-`;
`ГГГГММДД_Позывной`; транслит позывных: Лиса → `Lisa`, Ветер → `Veter`,
Кинолог → `Kinolog`, Борт → `Bort`, БПЛА → `copter`/`kopter`/`bpla`,
Пегас → `Pegas`. Несколько навигаторов у группы — суффикс через `_` или `-`
(`20200421_Lisa1_2`, `20200421_Lisa2_Mohnatiy`). Имя файла `.plt` = имя
трека; обработанные треки — прямо в `10-Tracks`, необработанные — в
`10-Tracks/ГГГГММДД/`.

**Цвет (п. 20–23):** схема выбирается на поиск и согласуется с
координатором; по умолчанию схема 1 — пешие красный, синий, редко зелёный;
Ветра розовые; Борты и БПЛА — жёлтый, голубой, белый, толщина 1. Другие
допустимые схемы: «радуга», по поисковым дням. Чёрный зарезервирован для
задач (`Zadacha<N>_ГГГГММДД`, толщина 1, пунктир). Сомнительные треки —
пунктир.

**Что из этого следует для ozi-rs:**

- список скачков по трекам — Dist и KPH до соседней точки, переход к
  «вершине», удаление вершины; «удалить и разделить» — для разрывов;
- проверка имени по п. 14–15 и исправление: транслит, `-`/пробел → `_`;
- схема цвета на поиск с правилами по типу группы (Lisa, Veter, Bort, …),
  чёрный — только задачи, пунктир — для сомнительных;
- подсказка о порядке: фильтр после обрезки;
- «индекс 4» — после того, как будет на чём его проверить.
