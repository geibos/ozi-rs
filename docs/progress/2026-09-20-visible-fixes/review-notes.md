Скриншоты реального окна: `.sisyphus/evidence/review-2026-09-19/` (01-workspace-maps-tab.png, 02-tracks-tab.png, 03-track-inspector.png). Что на них видно:

- Maps-таб пишет «No maps in this project», хотя карта активна и отрисована. Dead end от 16.07 закрыт кнопкой Open project, а не причиной.
- Иконочные кнопки в строках треков выглядят пустыми серыми квадратами, три на строку.
- Длительность треков на 5–12 км показана как 404, 629 и 634 часа. Либо статистика, либо разбор меток времени врёт, UI это не помечает.
- Оранжевая подсказка «Format: YYYYMMDD_Callsign» висит почти под каждой строкой.
- Прямые красные линии-выбросы через всю карту. Это то, что должен чинить CJ-4, но именно это видишь первым.
- Интерфейс по умолчанию английский, переключатель ru/en спрятан в Cmd-K. Переведены три экрана, остальные шесть на хардкод-английском.
- Клик по элементу с именем трека (xpath contains по имени) переключил видимость и сделал проект «Unsaved», инспектор не открылся. Возможно, селектор попал в кнопку видимости, поэтому багом строки это не названо.

Почему агенты этого не ловили:

- 22 из 30 фронтенд-тестов (`src/test/*.test.ts`) читают файл компонента через readFileSync и проверяют toContain. Пять из семи новых июльских тестов такие же. Рендерит компонент один файл (ui-primitives.test.ts). 268 зелёных тестов не поймали бы ни один пункт выше.
- E2E-сценарий один: нарисовать три точки (tools/ozi-rs-mcp/tests/smoke_core_workflow.rs). Срезы CJ-7, CJ-4, CJ-3 своих smoke не получили.
- У агентов нет глаз. Tier-1 capture_screenshot из MCP даёт чёрный кадр (нет Screen Recording). Appium снимает весь экран, пишет base64 вместо PNG, сессия умирает через 60 с простоя. Причина: `.mcp.json` запускает `target/release/ozi-rs-mcp`, собранный 26.05; июльские фиксы (newCommandTimeout=600, decode_screenshot_body) в бинарь не попали. `just smoke` собирается из исходников и этим не страдает.
- ADR-0024 запретил Playwright как доказательство. Для IPC верно. Побочный эффект: браузерный стенд с mock-IPC, на котором агент мог бы просто смотреть на экран, никто не построил. Отсюда редизайн с 12 регрессиями и невидимые треки, которые заметил только человек.
- 14 «taste»-скиллов (.agents/skills, .claude/skills; Leonxlnx/taste-skill), установленные в мае, заточены под лендинги и маркетинг, не под плотный десктопный GIS-инструмент.

## Можно ли спасти и как делать UI с агентами

Спасать. Ядро Rust здоровое: чистые слои, атомарные загрузки, кодировки, typed IPC, честные тесты. Rewrite с нуля сожжёт именно это и через два месяца приведёт в ту же точку, потому что цикл работы над UI останется прежним. Переписывать нужно цикл, а экраны перестраивать по одному внутри него.

План:

1. Гигиена, полдня. Закоммитить срез 15–16.07 (зелёный). Запушить main. Пересобрать ozi-rs-mcp, выдать Screen Recording терминалу и MCP.
2. Глаза для агента, 1–2 дня. Стенд `just dev-ui` с mock-слоем поверх сгенерированного bindings.ts и фикстурным проектом Lavrovo. Playwright снимает скриншот каждого экрана и состояния. ADR-0024 расширить: Playwright для визуальной итерации и компонентных тестов, Appium остаётся интеграционным гейтом. Скриншот «до/после» обязательный артефакт любого UI-изменения.
3. Дизайн-контракт, один день с владельцем. Один файл: токены (Zinc/Teal уже есть), плотность, типографика, состояния строк, иконки, пустые состояния, русский по умолчанию. Taste-скиллы убрать.
4. Тесты. Запрет readFileSync-тестов для нового кода. Компонентные тесты через @testing-library/svelte (уже в зависимостях). Один smoke на каждый CJ.
5. Пилот. Один экран, Library/Tracks: строки, иконки, статистика, пустые состояния, русский. Оценка только по скриншотам. Потом инспектор, потом BundleLoader.
6. Параллельно ядро: причины «629 часов» и линий-выбросов. Это Rust, там агенты работают хорошо.
